# Shale benchmark plan

Goal: measure Shale against **Obsidian**, **ZenNotes**, and **QOwnNotes** on the
same plain-Markdown vaults, and track Shale's own hot paths over time.

Everything lives under `bench/` (this directory). Nothing outside `bench/` is
touched by the harness. `bench/results/` holds raw JSON + screenshots;
`bench/vaults/` holds generated corpora. Both are disposable.

## Contenders on this machine (verified 2026-10-28)

| App | Version | Install | Engine | Vault to point at |
|---|---|---|---|---|
| shale | 0.1.0 | `target/release/shale` (build first) | Rust + Zed gpui (wgpu/Vulkan) | arg: vault path |
| Obsidian | 1.14.5 | Flatpak `md.obsidian.Obsidian` | Electron | URI `obsidian://open?path=` |
| ZenNotes | 2.77.0 | `/opt/ZenNotes/ZenNotes` + `zn` CLI 0.11 | Electron | `--user-data-dir` (verify) |
| QOwnNotes | 26.1.14 | RPM `/usr/bin/QOwnNotes` | Qt | `--portable` + seeded conf |

Fairness levers:
- All four open the **same vault copy**. The real corpus is
  `~/Nextcloud/Documents/Dnd` (172 notes, 14 MB) — already the shared vault of
  Obsidian and ZenNotes. **Never benchmark against the originals**; the harness
  copies.
- Obsidian runs with **no community plugins** (vanilla `.obsidian` only).
- Shale must be benchmarked **release-built**; the debug binary (590 MB) is not
  a fair representative. Build with
  `CARGO_TARGET_DIR=bench/target-release cargo build --release` so the other
  agent's `target/` lock is never contended.

## Corpora (generated by `gen_vault.py`)

| Name | Notes | Purpose |
|---|---|---|
| `dnd` | copy of the real Dnd vault (172) | realistic, already used by the rivals |
| `medium` | ~2 000 | indexing/search scaling |
| `large` | ~20 000 | stress; where rivals hurt |

Synthetic notes carry frontmatter, wikilinks (dense enough to make link
indexing measurable), tags, tasks, tables, code fences, embeds — the features
each app claims to index.

## Tiers

### Tier 1 — cross-app, fully automatable (the headline numbers)

1. **Cold start** (`cold_start.py`): launch, poll `niri msg --json windows`
   until the app's window maps → t₀→mapped. Then grim-poll the window region
   until pixels change → t₀→first paint. One warm-up run discarded, then N=5.
2. **Vault open / index**: same launch, but timed until the app is
   *responsive* (per-app readiness probe: quick-open opens a note in shale;
   search returns in Obsidian/ZenNotes; note list populated in QOwnNotes).
   Recorded per corpus size → scaling curves.
3. **Memory** (`mem_sample.py`): sum **PSS** from `smaps_rollup` across the
   whole process tree (flatpak/Electron spawn children; RSS double-counts
   shared pages). Sampled: idle-after-open, after opening the largest note,
   after a full-vault search.
4. **Search latency**: end-to-end full-vault search. Scriptable where possible
   (`zn search --json`); GUI-timed via ydotool + grim elsewhere.
5. **Footprint**: install size + per-vault metadata bloat — `.obsidian/` vs
   `.shale/` vs `.zennotes/` vs `notes.sqlite` after opening the same vault.
6. **Round-trip fidelity** (`roundtrip.sh`): open+save every note in each app
   against a vault copy, `diff -r` vs the original. Objectifies Shale's
   "near-perfect Obsidian compatibility" goal: frontmatter, wikilinks,
   whitespace, trailing newline.

### Tier 2 — Shale-internal microbenchmarks (criterion, `crates/core`)

`mdstyle` scan, wiki-link resolution/backlinks, `fuzzy`, `watch` diff,
`search`, `table` edit. Doesn't compare cross-app; explains Tier 1 and catches
regressions. Pure Rust, no new system deps. **Deferred**: adding a `[[bench]]`
section touches `crates/core/Cargo.toml`, an existing file — do it when the
other agent is done.

### Tier 3 — GUI keystroke→frame latency (ydotool, installed)

`latency.py`: `ydotool key` a keystroke into the focused window, grim-poll the
window region, report frames-until-change × refresh interval. Needs
`ydotoold` running (see README). Same method for all four apps → the one
number where Shale's Rust+gpui stack must beat Electron/Qt or explain why not.
Shale-only bonus: gpui `test-support` headless tests can measure
keystroke→paint internally with zero injection.

### Tier 4 — feature-parity matrix (qualitative)

Score each app against Shale's PROJECT.md goals: wikilinks/backlinks, graph
view, vim bindings, MCP, bases/tables, theming, templates, splits, command
palette, spellcheck. Perf is Electron's losing game; this is where shale
actually competes.

## Caveats

- **Obsidian is proprietary.** Measuring performance is fine; never copy its
  assets/prose into this repo (same rule as `refs/README.md`).
- Cold vs warm start reported separately; flatpak gets one discarded warm-up.
- ZenNotes/QOwnNotes config: use isolated config dirs (`--user-data-dir`,
  `--portable`) so benchmarking doesn't mutate the user's real settings —
  **flag to verify** in the smoke test.
- Memory: PSS, process-tree summed, sampled at identical checkpoints.
- Report machine specs with results: Fedora, niri 26.04 (Wayland),
  DP-4 3840x1080@120Hz scale 1.25.

## Execution order

1. ✅ harness scripts (this directory)
2. release build of shale (`CARGO_TARGET_DIR=bench/target-release`)
3. generate corpora; smoke-test each launcher + readiness probe
4. Tier 1 runs → `bench/results/`
5. Tier 4 matrix
6. Tier 2 criterion benches (when `crates/core/Cargo.toml` is free to touch)
